## E1. Питання, які можуть поставити (знай відповіді)
- **Як працює JWT?** Сервер підписує токен (HS256) із `sub`=id користувача й терміном `exp`; клієнт шле його в `Authorization: Bearer`; сервер перевіряє підпис і термін.
- **Як зберігаються паролі?** Не відкрито: PBKDF2-SHA256, випадкова сіль, 100 000 ітерацій, порівняння через `hmac.compare_digest`.
- **Як уникли подвійного бронювання?** Перевірка перетину інтервалів у транзакції, `SELECT FOR UPDATE` по майстру, частковий UNIQUE-індекс; при гонці друга транзакція отримує 409.
- **Навіщо денормалізація `master_id` у bookings?** Щоб перевіряти зайнятість без JOIN до services і мати унікальний індекс (master_id, start_at).
- **Що таке транзакція / ACID?** Група операцій, що виконується атомарно; тут — перевірка + вставка запису.
- **Захист від SQL-ін'єкцій?** Параметризовані запити через ORM, значення не підставляються в SQL рядками.
- **Навіщо індекси і де вони?** Прискорюють пошук/JOIN: місто+категорія, FK, слоти.
- **Як рахується покриття?** pytest-cov відстежує, які рядки виконались під час тестів; відсоток виконаних рядків.
- **Чому 401, 403, 404, 409, 422?** 401 — не автентифікований, 403 — немає прав, 404 — не знайдено, 409 — конфлікт (зайнятий слот), 422 — невалідні дані.
- **Чим відрізняється PUT від POST?** PUT повністю замінює ресурс (графік), POST створює.
- **Як працює CI?** GitHub Actions на кожен push ганяє pylint і pytest на Ubuntu та Windows; падає, якщо покриття <80%.
