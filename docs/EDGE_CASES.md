# Крайні випадки (C2)

| № | Випадок | Оброблено | Де / автотест |
|---|---|---|---|
| 1 | Двоє клієнтів одночасно на один слот | Так: перевірка в транзакції + частковий UNIQUE-індекс, друга спроба → 409 | `scheduling.check_slot`, `uq_booking_active_slot`; test_double_booking_rejected |
| 2 | Запис у минуле / поза графіком / не за сіткою слотів | Так, 400 з поясненням | test_booking_in_past_rejected, test_booking_outside_schedule_rejected, test_booking_off_grid_rejected |
| 3 | Пошук без результатів, порожня БД | Так, порожній список (не помилка) | test_search_empty_db |
| 4 | Рейтинг 0 / 6 / -1, порожній email, надто короткий пароль, текст >1000 символів | Так, 422 | test_review_rating_bounds, test_invalid_email_rejected, test_weak_password_rejected |
| 5 | Необроблений виняток на сервері | Так: глобальний handler повертає JSON 500 і пише в лог, сервер не падає | test_unhandled_error_returns_json_500 |

Додатково: межові значення часу (початок і кінець зміни) — test_booking_boundary_values;
видалення послуги, за якою є записи — 409; чужий запис — 403.

У клієнті (B): при недоступному сервері `api.js` кидає «Немає зʼєднання з сервером».

## Відповідність пунктам C2
(1) валідація введення — Pydantic-схеми; (2) порожні/некоректні дані — 422/400; (3) винятки без аварійного
завершення — глобальний handler; (4) межові значення — тести ціни, тривалості, рейтингу, кінця зміни;
(5) чистий лог — під час прогону тестів немає необроблених винятків (окрім навмисного в test_system).
